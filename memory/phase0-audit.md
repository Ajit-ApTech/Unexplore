## How Key Systems Work

### Tabs / Webviews
- **Rust**: `TabProjectionModel` in `frame/src/domain/tabs/tabs-model.ts` manages tab state with revision-based admission
- **IPC**: `commands.tabsOpen()`, `commands.tabsNavigate()`, `commands.tabsActivate()` etc.
- **Flow**: Tab creation → Rust projection model → Svelte projection → DOM
- **View binding**: Many Items → Few Views (max 64 live views), lazy webview creation on first navigation
- **Profile isolation**: Per-profile SQLite store + webview data partition (WKWebsiteDataStore / WebView2 user-data-folder)

### Ad/Tracker Blocker
- **Native network policy**: `zephium-blocker` crate compiles EasyList + EasyPrivacy into platform-specific rules
- **macOS**: `WKContentRuleList` installed per raw view
- **Windows**: In-process `WebResourceRequested` synchronous matcher
- **Linux**: `WebKitUserContentFilter` compiled JSON cached per view
- **Default**: Blocked until explicit enable; first navigation waits for non-empty policy

### IPC / Commands
- Generated by `tauri-specta` from `frame/src/shared/ipc/bindings.ts`
- All commands go through `__TAURI_INVOKE` with `expectedProfile` parameter
- Types are DTOs serialized/deserialized
- Panel has NO generic Tauri capabilities; main view has only required window controls

### Privileged Chrome ↔ Rust Communication
- **Caller-labelled IPC**: Tauri-injected caller label + Rust validation
- `authorize(&caller, CallerPolicy::Main, "command")` guards all privileged commands
- Panel cannot select main view as event target
- Commands validate/clamp IDs, URLs, strings, coordinates

### Profiles
- **Incognio/Ephemeral**: Non-persistent, no cookies/cache/SW retained between launches
- **Persistent**: Own SQLite store, profile registry shared via `meta.sqlite`
- **Profile data**: settings, themes, bookmarks/pins live in SQLite; history/favicon cache per-profile

### Work/Agentic Browsing
- Separate `zephium-agentic` crate: pure browser-execution identity, lifecycle, semantic/action/policy contracts
- `page_assist` domain: status, ask, stop, cite, focus, decide, continue, new, history, open, delete, pick, detach, close
- Work composition: trusted macOS engine/Store adapter (optional feature)
- Work execution: scoped runtime, native actions, forms, artifacts, results, evidence

### Security Model (from `docs/security-model.md`)
- **Zone 1**: Rust/native (trusted) - owns state, persistence, windows
- **Zone 2**: Application WebViews (semi-trusted) - chrome, panel, overlays; bundled assets only
- **Zone 3**: Tab WebViews (untrusted) - raw Wry child WebViews, NO IPC bridge
- **Key invariant**: Tabs receive no Tauri command bridge, no Wry IPC, no custom protocol

## Security Concerns Noted

1. **IPC Exposure**: All commands go through Tauri IPC with `expectedProfile` validation - need to ensure new agent commands follow same pattern
2. **CSP Configuration**: Currently quite permissive in dev (`unsafe-eval`, `unsafe-inline`); production CSP is stricter
3. **Capability Configuration**: Tauri `capabilities/` directory defines what's enabled; need to audit for new agent features
4. **Permission Config**: `desktop/src/capabilities/` - need review for agent-related permissions
5. **No secrets in page content**: Architecture explicitly prevents page content from being treated as instructions
6. **Profile data separation**: Incognito profiles bypass Store entirely - good for privacy

### Phase 3 → Phase 4 (Safe AI Agent) — COMPLETED
**Implemented across all 5 workstreams**:
1. **Workstream 1 (Native OS Keychain Credential Security)**:
   - Migrated account service from `zephium` to `unexplore` in `zephium-credentials/src/macos.rs` with backwards compatibility fallback for legacy credentials.

3. **Workstream 3 (Safe Boundary & Prompt Injection Defense)**:
